# frontend — 分镜 IR 的转换台与审阅器

React + TypeScript + Vite。两件事：**提交转换任务**、**审阅分镜 IR**。

产品边界决定了它的定位：交付物是 IR 本身，所以这个界面不是剪辑器，而是让人**看懂并查证**这份 IR
——每个镜头能不能溯源回原文、系统补了哪些画面、旁白占比是否合理。

## 开发

```bash
npm install
npm run dev          # http://localhost:5173，/api 自动代理到 127.0.0.1:8000
```

先把后端跑起来：

```bash
cd ../backend && .venv/bin/uvicorn server.app:app --port 8000
```

后端不在默认端口时：`VITE_API_TARGET=http://host:port npm run dev`。

## 构建部署

```bash
npm run build        # tsc -b + vite build → dist/
npm run preview
```

## 测试

```bash
npm test
```

两个套件：

**`tests/flow.test.tsx`** — 在 happy-dom 里驱动整个 App 跑交互流程，用桩后端替代真实转换：
提交 → 放到后台 → 从侧栏点回来 → 无人附着时跑完并弹通知 → 从历史打开产物 → 页签切换 →
失败原因摊开 → 资产卡编辑 → 保存后核对 ID 与跨引用逐字未变。
**类型检查与构建拦不住交互逻辑的断裂**，这条流程曾经真的断过（放到后台就再也回不去），
所以固化成回归测试。

**`tests/edit-validity.test.tsx`** — 对《药》全文归档施加一通编辑（资产卡 + 分镜呈现层），
断言 ID / 跨引用 / 台词旁白 / 原文 units 逐字未变，再把结果交给**真实的 Python 校验器**
（`lint_storyboard.py` + `check_fidelity.py`）复核。「改了不会破坏校验」这种话只有真跑校验器才算数——
早期版本把 `appearance` 当自由键值表编辑，就是被真实校验器抓出来的 schema 违规。
找不到 `../backend/.venv` 时自动跳过校验器那一段。

`dist/` 是纯静态产物，可挂任意静态服务器。此时前端与后端跨源，需二选一：

- 用 `VITE_API_BASE=https://api.example.com npm run build` 直连后端（后端已开 CORS，
  可用 `STORYBOARD_CORS_ORIGINS` 收紧来源白名单）；
- 或在网关把 `/api/*` 反代到转换服务。

## 界面

**历史记录（左侧常驻）** — 转换慢又花钱，产物不能只活在内存里。每次完成的转换由后端落盘到
`backend/runs/*.json`，服务重启不丢、换浏览器还在、可直接备份传阅。点一条即载入审阅，可删除。

**转换表单** — 粘贴或读取 `.txt`。文本框始终持有**整篇**原文，下方的分段选择器决定这次转哪一段，
两者互不打架。实时估算批数（后端默认 2500 字一批）好让人对耗时有预期。「严格模式」对应后端 `strict`：
软质量门重试耗尽时直接失败，而非择优降级交付。

**章节自动识别与分段选取** — `chapters.ts` 按优先级试多套标题模式：`第N章/回/节/卷`、
`Chapter N`、`1. 标题`、以及独占一行的汉字序号（《药》就是「一二三四」这种）。
只取命中数 ≥2 且优先级最高的那套——**宁可识别不出，也不要把正文里的句子误判成标题**
（识别不出就回退到全文/自定义）。首个标记之前的楔子/前言单独成段，不会被悄悄丢掉。

三种选法：**全文** / **按章节**（多选，按原文顺序拼接；只选一章时可再切前半章或后半章，
切点落在段落边界，不从句子中间劈开）/ **自定义分段**（按自然段指定起止）。

艺术风格 / 色调 / 目标平台 / TTS 音色是**预设下拉 + 自定义兜底**——这些字段在 schema 里是自由文本
（直接进 prompt 由 LLM 理解，不参与机器校验），预设只为省去手打，不该把人锁死在列表里。
切到「自定义」时当前值会带进输入框，所见即所发。

**历史资料卡** — 表单里按作品列出历次转换积累的人物 / 场景 / 道具 / 生物卡。选中某部作品后，
其资产库作为【已有资产库】随请求发给模型（后端 `seed_assets`），模型须沿用已有 ID 与描述。
**续写同一部小说的下一章时，角色不会换脸、场景不会改建**——这正是资产引用制防漂移的跨章延伸。

**任务面板（可离开）** — 转换在后端线程池里跑，**关掉页面不会中断**。面板上「放到后台，去开新转换」
随时可走；侧栏顶部常驻显示在跑的任务与最新一行日志，点回去就接上（`GET /jobs` + `attach`），
不必守着页面等。跑完弹桌面通知（权限在提交那一刻申请，必须由用户手势触发）。

这里的关键是**任务列表巡检独立于「是否正在看某个任务」**：巡检常驻运行（有任务在跑时 3s 一轮，
闲时 10s），负责让后台任务留在侧栏可点回来，也负责在没人附着时发现任务结束并播报。
早期版本把巡检的启动条件写成「已知有任务在跑」，成了先有鸡先有蛋——提交后从没刷新过列表，
一旦放到后台，任务就既看不见也回不去。`tests/flow.test.tsx` 专门守这条路径。

失败时把**未通过的原因直接摊开**：每次生成的校验/质量门报告逐行进日志流，
另在顶部单独高亮最终失败原因。报告超 60 行会截断并给出完整报告的落盘路径——
用户看不到工作目录，光说「未通过」等于没说。

`completed_with_warnings` 会把质量报告单独高亮出来，而不是混在成功里。

**分镜审阅** — 四个页签：

| 页签 | 内容 |
|---|---|
| 分镜 | 按集折叠；BGM 情绪曲线按镜头跨度铺成色带；镜头卡含景别/运镜/场景/角色/道具/台词/旁白/音效 |
| 资产卡 | C 角色 / S 场景 / P 道具 / A 生物，外貌只在这里出现（镜头层只写引用，从根上防漂移） |
| 原文溯源 | 逐句列出原文，标出被哪些镜头引用、是否念作旁白；**未被任何镜头覆盖的句子标红**，可一键筛选 |
| JSON | 原始 IR，可下载 |

镜头卡左边框颜色即推导来源（绿＝原文明写、黄＝系统补充、紫＝过渡镜）。
点镜头脚注的 `u0042` 之类溯源码，会跳到「原文溯源」页并高亮定位到那一句。

## 手动编辑分镜

「编辑分镜」开关打开后，镜头卡与资产卡就地变成表单。**编辑权只开在「呈现」那一侧**：

| | 字段 |
|---|---|
| 镜头可改 | 时长 / 景别 / 运镜 / 机位角度 / 场景 / 时间 / 天气 / 画面描述 / 氛围 / 音效 / 转场 / 角色表情·动作·位置 / 台词情绪 |
| 资产卡可改 | 名称 / 别名 / 外貌七项 / 服装名与外观 / 声音 / 性格 / 年代 / 内外景 / 默认光 / 机位 / 道具状态名与外观 / 物种 / 备注 / 画面描述 |
| 🔒 锁死 | 原文 units 文本、`source.unit_refs`、`derivation`、台词文本、旁白文本，以及**所有被跨引用的 ID**：资产 ID、`outfits[].id`、`states[].id` |

这条线不是随手划的。ID 锁死是因为镜头层靠它们引用资产（`location_ref` / `prop_refs.ref`+`state` /
`characters.ref`+`outfit` / `dialogue.character_ref`），改一个 lint 立刻报「引用不存在的资产」。
其余字段改了不影响校验——资产卡整个属于呈现侧。

另注意 `appearance`（age/gender/body/face/hair/eyes/distinguishing_marks）与
`voice`（tts_voice/tone）在 schema 里是 `additionalProperties: false` 的**白名单**，
所以按固定字段编辑而非自由键值表——多加一个键就是 schema 校验失败。

锁在这里，改完的产物依然是合法、可溯源、机器可校验的 IR——「剧情属于小说，呈现属于系统」，
编辑权正好落在系统那一侧。

改动实时反映在统计与 JSON 页签上；「保存修改」写回后端历史记录（记 `edited_at`，
创建时间与制作参数不动）。本地打开的 JSON 不入库，改完请下载。

顶栏「打开本地 JSON」可直接审阅归档产物（如 `../backend/tests/real_text_yao/output_merged.json`），
不需要连后端、不花 API 费用。

## 结构

```
src/
  types.ts        NovelStoryboard v0.4 的 TS 镜像（对齐 backend/schema/storyboard.schema.json）
  labels.ts       枚举 → 中文标签；IR 存英文枚举供机器消费，界面一律显示中文
  presets.ts      艺术风格/色调/平台/音色的预设选项（自由文本字段，允许自定义）
  chapters.ts     章节标题识别 + 半章/自定义分段切取
  notify.ts       桌面通知（转换是分钟级任务，不该让人守着页面）
  resolve.ts      溯源索引：资产 ID → 名称、原文句 → 引用它的镜头、覆盖率/旁白占比统计
  edit.ts         分镜的不可变编辑 + 可编辑边界（锁死字段在此声明）
  api.ts          后端 HTTP 契约（转换 / 任务 / 历史 / 资产库）
  useJob.ts       提交 + 轮询 + attach（重新接上后台仍在跑的任务）
  components/     HistoryPanel / ConvertForm / ChapterPicker / AssetLibraryPicker
                  SelectOrCustom / JobPanel / StoryboardView / EpisodeView / ShotCard
                  AssetsView / SourceView
```

`types.ts` 的可选性以 schema 的 `required` 为准：非必填一律 `?`，渲染层不假设其存在
（弱模型产出的合法 IR 也常常字段稀疏）。
