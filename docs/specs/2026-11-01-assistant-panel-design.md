# Agent 助手面板设计

日期：2026-11-01。

背景：工作台改版规格（`docs/specs/2026-11-01-workspace-redesign-design.md`）第 11 节第 4 条的最后一项，「对话式下指令，能看到它在跑什么任务」。风格参考图、导出剪辑工程已完成。

## 0. 目标

- 每部小说有一个助手：能回答这部小说的进度和内容，能替用户发起操作，能按指令改内容。
- 花钱的操作和改内容都要用户在界面上点确认，金额由服务端算，不信模型报的数。
- 对话存在服务端，换设备、刷新页面都能接上。
- 实现用 LangGraph 的智能体与「中断等确认」，工具直接调服务端现有函数（用户定的方案 A）。

## 1. 拆分

三个子计划，各自能单独交付：

1. **会话与查询**：助手页签、流式回答、对话存档、只读工具、跳转按钮。本文第 2–6 节写到可实施的程度。
2. **发起操作**：生成分镜、出关键帧、出片、配音合成、导出；花钱的先出确认卡。见第 7 节。
3. **改内容**：改镜头、资产卡、主线剧情；先给改动对比，应用后能撤销。见第 8 节。

子计划 2、3 在本文只定接口与原则，做到时再补细节（在本文追加小节，不另起文档）。

## 2. 用户能看到的（子计划 1）

### 2.1 入口

- 右侧动态面板顶部的页签位（改版规格第 7 节预留的）加「助手」，与「动态」并列。
- 顶栏铃铛旁加一个助手图标按钮，点了打开面板并切到「助手」。
- 切到「助手」时面板宽 400px，「动态」仍是 320px。
- 只在进入某部小说后可用；书架页不显示助手入口。

### 2.2 面板

```
┌ 动态 │ 助手 ────────────── 清空 ┐
│ 当前：第三章 · ③ 检查修改         │
│                                  │
│  你：第 3 章还有哪些镜头没出片？  │
│  ▸ 查了第三章出片状态 ✓           │
│  助手：还有 SH004、SH007 两段……   │
│        [去 ⑤ 出片]                │
│                                  │
│ ┌──────────────────────────┐    │
│ │ 问点什么，或让我帮你做…   │ ⏹ │
│ └──────────────────────────┘    │
└──────────────────────────────────┘
```

- **当前位置条**：显示当前所在的章节和步骤，随页面切换实时变化。没进章节时显示「概览」。
- **消息**：
  - 用户消息靠右，助手消息靠左。
  - 助手的文字逐字出现。
  - 只渲染换行、加粗（`**…**`）和无序/有序列表；用很小的自写渲染器，不加依赖，不渲染 HTML。
- **工具调用**：每次调用折叠成一行，「▸ 查了第三章出片状态」。进行中显示转圈，完成 ✓，失败 ✕。点开看参数与结果摘要（等宽字）。
- **跳转按钮**：来自 `goto` 工具（第 4 节），显示在那条回答下方，点了进入对应章节和步骤。
- **输入框**：
  - Enter 发送，Shift+Enter 换行；输入法组字中按 Enter 不发送。
  - 回答中发送按钮变「停止」。停止会断开请求；已出来的文字保留并标「已中断」。
  - 最长 2000 字，超出不让发。
- **空对话**：显示三个示例问题，点一下直接发出：
  - 「这部小说现在进行到哪了？」
  - 「当前这一章还有什么没做完？」
  - 「列出主要角色和他们的设定」
- **清空**：右上角「清空」，走 `useConfirm`，确认后删除服务端存档。
- **报错**：
  - 每日上限（429）：「今天的助手消息已用完，明天再来」，输入框禁用。
  - 并发（409）：「上一条还在回答」。
  - 其他错误：在对话里显示一条报错消息，可点「重试」重发上一条。
- 所有新文字进 `zh.ts` 与 `en.ts`。

### 2.3 语言

前端每条消息带上界面语言（`zh` / `en`），系统提示要求用这种语言回答。

## 3. 后端结构

新包 `backend/assistant/`：

- `graph.py`：`build_agent(chat_model, tools, checkpointer)`。
  - 用 `langgraph.prebuilt.create_react_agent`。项目没有装 `langchain` 包，`langchain.agents.create_agent` 不可用，不为它加依赖。
  - 模型由 `pipeline.chat.build_chat_model` 创建，沿用重试与 `UsageCallback`。
  - 每轮的 `recursion_limit` 设为 25（约 12 次工具调用）。超了就结束本轮，回一句「步骤太多，先停在这里」。
  - 发给模型的历史只取最近 20 条消息：用 `pre_model_hook` 裁剪，存档里保留全量。裁剪不能把工具调用和它的结果拆开。
- `tools.py`：只读工具（第 4 节）。
  - 每个工具从 `RunnableConfig["configurable"]` 读 `user_id`、`novel_id`，由服务端注入，模型看不到也改不了。
  - 只调 `server/novels.py`、`server/summary.py` 等现有函数，不发 HTTP。
- `store.py`：对话存档。
  - 用 `langgraph-checkpoint-sqlite` 的 `SqliteSaver`，新增依赖 `langgraph-checkpoint-sqlite`。
  - 每部小说一个文件 `<小说目录>/assistant.sqlite`，`thread_id` 固定为 `"main"`。删除小说时随目录一起删除；清空对话时删掉这个文件。
- `prompts/assistant.md`：系统提示词。写明：
  - 只管当前这部小说；
  - 不知道就查工具，不要编；
  - 回答简短；
  - 子计划 1 里不能执行任何操作，要做事就给跳转按钮，让用户自己去点；
  - 不暴露内部编号以外的系统信息。
- 每次请求在系统提示后附一段「当前位置」：章节标题与编号、版本编号、步骤、界面语言。这段只发给模型，不写进存档。

## 4. 只读工具（子计划 1）

都限定在当前小说内。章节参数接受章节编号、「第三章」这类序号，或标题的一部分；解析不出来时返回候选列表。

| 工具 | 参数 | 返回 |
|---|---|---|
| `novel_overview` | — | 复用 `summary` 的数字与各章所在步骤 |
| `chapter_status` | `chapter` | 版本列表（编号、状态、创建时间）、采用的版本、当前步骤、卡在哪 |
| `shots_get` | `chapter`, `shot_ids?` | 采用版本里镜头的要点字段：编号、景别、画面、台词、时长；一次最多 20 个，不给 `shot_ids` 就取前 20 个 |
| `assets_find` | `query?`, `kind?` | 资产卡摘要：编号、类型、名字、别名、设定的前 200 字；最多 20 张 |
| `plot_get` | — | 主线剧情与各章梗概 |
| `film_status` | `chapter` | 各段状态、失败原因、已花与预估金额、合成状态 |
| `jobs_running` | — | 本小说在跑的任务、进度、最新一行日志 |
| `goto` | `chapter?`, `step` | 没有副作用；返回一个跳转目标，前端渲染为按钮 |

- 工具返回的文本最长 4000 字符，超出截断，并注明「还有 N 条未列出」。
- 返回里不含服务器路径、密钥、其他用户的任何信息。报错经过 `_hide_root`。
- `step` 取值与前端 `currentStep` 的六步一致。

## 5. 接口（子计划 1）

都依赖 `novel_user`（登录，且只能访问自己的小说；别人的返回 404）。

- `POST /novels/{nid}/assistant/messages`
  - 请求体：`{ text, lang, where: { chapter_id?, version_id?, step? } }`。
  - 返回 SSE（`text/event-stream`），事件：
    - `token` `{text}`：文字片段；
    - `tool_start` `{id, name, args}`：工具开始；
    - `tool_end` `{id, ok, summary}`：工具结束；
    - `goto` `{chapter_id?, step}`：跳转目标；
    - `done` `{}`：本轮结束；
    - `error` `{message}`：出错。
  - 实现：`agent.stream(..., stream_mode=["messages", "updates"])` 转成上面的事件。客户端断开时停止迭代，已生成的消息照常留在存档里。
- `GET /novels/{nid}/assistant`：返回历史，`{ messages: [{role, text, tools?, goto?}] }`，只给显示用的字段。
- `DELETE /novels/{nid}/assistant`：清空。没有存档也返回成功。

**限制**

- 每人每天的消息上限，环境变量 `STORYBOARD_ASSISTANT_DAILY`，默认 200。超过返回 429。按 UTC 日期计数，计数存在用量记录里。
- 同一部小说同时只跑一轮，进程内加锁；第二个请求返回 409。
- 用量：每轮结束（含中断、出错）按 `purpose="assistant"` 记一笔 `usage.record`，带 `novel_id`。管理后台的用量页照常可见。

## 6. 测试（子计划 1）

- **后端**（不调真实模型）：
  - 用 `GenericFakeChatModel`，或一个按脚本返回 `AIMessage(tool_calls=…)` 的假模型，驱动整轮对话。
  - 每个工具：返回字段、截断、章节解析与候选列表；对别人的小说拿不到数据。
  - SSE：事件顺序是 `tool_start` → `tool_end` → `token`… → `done`，`goto` 事件带对的目标。
  - 存档：两次请求之间历史接得上；`GET` 返回的历史正确；`DELETE` 之后为空，文件已删。
  - 历史裁剪：超过 20 条时发给模型的不超过 20 条，且不拆开工具调用与结果。
  - 限制：第 201 条返回 429；并发第二个请求返回 409。
  - 用量：一轮之后有一笔 `purpose="assistant"`。
  - 返回内容里没有服务器根路径。
- **前端**：
  - 发送、逐字显示、工具行的三种状态与展开；
  - 跳转按钮进对应章节和步骤；
  - 停止后标「已中断」；
  - 清空要确认；
  - 空对话示例问题；
  - 429 时禁用输入；
  - 输入法组字中 Enter 不发送。
- **冒烟**：`backend/assistant/smoke.py` 用真实模型对一部示例小说问一个问题，打印回答和用量。要花几分钱，由用户手动运行，开发与测试中不运行。

## 7. 子计划 2：发起操作（原则）

- **工具**：`generate_storyboard(chapter)`、`render_keyframes(chapter)`、`film_run(chapter, clip_ids?)`、`compose(chapter)`、`export_fcpxml(chapter)`。
  - 内部调用与接口相同的函数，因此鉴权、预估、花费上限、过期检查都相同。
- **确认**：
  - 要花钱的工具先算预估（服务端），然后调用 `langgraph.types.interrupt({...})` 暂停。
  - SSE 发出 `confirm` 事件：`{ id, action, chapter, amount, detail }`。
  - 前端在对话里渲染确认卡，上面有「确认」「取消」两个按钮。
  - 点按钮后调 `POST /novels/{nid}/assistant/resume`，请求体 `{ id, decision: "approve" | "reject" }`。服务端用 `Command(resume=…)` 接着跑，同样流式返回。
  - 恢复时重新算一次预估，与卡上的金额不一致就不执行，重新出卡。
  - 不花钱的操作（例如导出）不出确认卡，直接执行。
- **进度**：
  - 执行后返回任务编号；对话里出现一张任务卡，复用 `useJob`、`useFilm`、`useCompose` 显示进度。
  - 任务完成后，这张卡变成结果摘要和跳转按钮。
- **未处理的确认卡**：存档里处在中断状态时，`GET` 返回这张待确认的卡。此时用户如果发新消息，先自动按「取消」处理这张卡。

## 8. 子计划 3：改内容（原则）

- **工具**：`shots_edit(chapter, edits)`、`asset_edit(card_id, fields)`、`plot_edit(...)`。
  - 模型给出要改成什么，服务端算出改动对比，然后 `interrupt` 暂停。
- **对比卡**：SSE 发出 `diff` 事件，前端按字段逐条显示「原 → 新」，带「应用」「放弃」两个按钮。之后同样走 `resume`。
- **应用**：
  - 改镜头时，以采用版本为底生成一个新版本（与界面上「保存修改」相同），不覆盖原版本。
  - 改资产卡和主线剧情时直接写入，并在服务端记下改之前的值。
- **撤销**：对比卡在应用后变成「已应用 · 撤销」。撤销时，镜头切回原来采用的版本；资产卡和主线剧情写回改之前的值。只能撤销最近一次应用，且要求之后没有被别处再改过，否则提示无法撤销。

## 9. 不做

- 一部小说多串对话、对话搜索、导出对话。
- 书架页的跨小说助手。
- 语音输入、上传图片给助手。
- 让模型自己决定花钱、跳过确认。
- 助手修改小说参数、删除章节或版本、删除小说。
- 后端报错文字英文化（另一件事）。
