# Agent 助手面板设计

日期：2026-11-01。

背景：工作台改版规格（`docs/specs/2026-11-01-workspace-redesign-design.md`）第 11 节第 4 条的最后一项，「对话式下指令，能看到它在跑什么任务」。风格参考图、导出剪辑工程已完成。

## 0. 目标

- 每部小说有一个助手：能回答这部小说的进度和内容，能替用户发起操作，能按指令改内容。
- 花钱的操作和改内容都要用户在界面上点确认，金额由服务端算，不信模型报的数。
- 对话存在服务端，换设备、刷新页面都能接上。
- 实现用 LangGraph 的智能体与「中断等确认」，工具直接调服务端现有函数（用户定的方案 A）。

## 1. 拆分

三个子计划，各自能单独交付：

1. **会话与查询**：助手页签、流式回答、对话存档、只读工具、跳转按钮。本文第 2–6 节写到可实施的程度。
2. **发起操作**：生成分镜、出片、配音合成、导出；花钱的先出确认卡。见第 7 节（7.1 起是实施细节）。
3. **改内容**：改镜头、资产卡、主线剧情；先给改动对比，应用后能撤销。见第 8 节（8.1 起是实施细节）。

子计划 2、3 在本文只定接口与原则，做到时再补细节（在本文追加小节，不另起文档）。

## 2. 用户能看到的（子计划 1）

### 2.1 入口

- 右侧动态面板顶部的页签位（改版规格第 7 节预留的）加「助手」，与「动态」并列。
- 顶栏铃铛旁加一个助手图标按钮，点了打开面板并切到「助手」。
- 切到「助手」时面板宽 400px，「动态」仍是 320px。
- 只在进入某部小说后可用；书架页不显示助手入口。

### 2.2 面板

```
┌ 动态 │ 助手 ────────────── 清空 ┐
│ 当前：第三章 · ③ 检查修改         │
│                                  │
│  你：第 3 章还有哪些镜头没出片？  │
│  ▸ 查了第三章出片状态 ✓           │
│  助手：还有 SH004、SH007 两段……   │
│        [去 ⑤ 出片]                │
│                                  │
│ ┌──────────────────────────┐    │
│ │ 问点什么，或让我帮你做…   │ ⏹ │
│ └──────────────────────────┘    │
└──────────────────────────────────┘
```

- **当前位置条**：显示当前所在的章节和步骤，随页面切换实时变化。没进章节时显示「概览」。
- **消息**：
  - 用户消息靠右，助手消息靠左。
  - 助手的文字逐字出现。
  - 只渲染换行、加粗（`**…**`）和无序/有序列表；用很小的自写渲染器，不加依赖，不渲染 HTML。
- **工具调用**：每次调用折叠成一行，「▸ 查了第三章出片状态」。进行中显示转圈，完成 ✓，失败 ✕。点开看参数与结果摘要（等宽字）。
- **跳转按钮**：来自 `goto` 工具（第 4 节），显示在那条回答下方，点了进入对应章节和步骤。
- **输入框**：
  - Enter 发送，Shift+Enter 换行；输入法组字中按 Enter 不发送。
  - 回答中发送按钮变「停止」。停止会断开请求；已出来的文字保留并标「已中断」。
  - 最长 2000 字，超出不让发。
- **空对话**：显示三个示例问题，点一下直接发出：
  - 「这部小说现在进行到哪了？」
  - 「当前这一章还有什么没做完？」
  - 「列出主要角色和他们的设定」
- **清空**：右上角「清空」，走 `useConfirm`，确认后删除服务端存档。
- **报错**：
  - 每日上限（429）：「今天的助手消息已用完，明天再来」，输入框禁用。
  - 并发（409）：「上一条还在回答」。
  - 其他错误：在对话里显示一条报错消息，可点「重试」重发上一条。
- 所有新文字进 `zh.ts` 与 `en.ts`。

### 2.3 语言

前端每条消息带上界面语言（`zh` / `en`），系统提示要求用这种语言回答。

## 3. 后端结构

新包 `backend/assistant/`：

- `graph.py`：`build_agent(chat_model, tools, checkpointer)`。
  - 用 `langgraph.prebuilt.create_react_agent`。项目没有装 `langchain` 包，`langchain.agents.create_agent` 不可用，不为它加依赖。
  - 模型由 `pipeline.chat.build_chat_model` 创建，沿用重试与 `UsageCallback`。
  - 每轮的 `recursion_limit` 设为 37：每次工具循环占 3 步（`pre_model_hook`、模型、工具），约 12 次工具调用。超了就结束本轮，回一句「步骤太多，先停在这里」。
  - 发给模型的历史只取最近 20 条消息：用 `pre_model_hook` 裁剪，存档里保留全量。裁剪不能把工具调用和它的结果拆开。
- `tools.py`：只读工具（第 4 节）。
  - 每个工具从 `RunnableConfig["configurable"]` 读 `user_id`、`novel_id`，由服务端注入，模型看不到也改不了。
  - 只调 `server/novels.py`、`server/summary.py` 等现有函数，不发 HTTP。
- `store.py`：对话存档。
  - 用 `langgraph-checkpoint-sqlite` 的 `SqliteSaver`，新增依赖 `langgraph-checkpoint-sqlite`。
  - 每部小说一个文件 `<小说目录>/assistant.sqlite`，`thread_id` 固定为 `"main"`。删除小说时随目录一起删除；清空对话时删掉这个文件。
- `prompts/assistant.md`：系统提示词。写明：
  - 只管当前这部小说；
  - 不知道就查工具，不要编；
  - 回答简短；
  - 子计划 1 里不能执行任何操作，要做事就给跳转按钮，让用户自己去点；
  - 不暴露内部编号以外的系统信息。
- 每次请求在系统提示后附一段「当前位置」：章节标题与编号、版本编号、步骤、界面语言。这段只发给模型，不写进存档。

## 4. 只读工具（子计划 1）

都限定在当前小说内。章节参数接受章节编号、「第三章」这类序号，或标题的一部分；解析不出来时返回候选列表。

| 工具 | 参数 | 返回 |
|---|---|---|
| `novel_overview` | — | 复用 `summary` 的数字与各章所在步骤 |
| `chapter_status` | `chapter` | 版本列表（编号、状态、创建时间）、采用的版本、当前步骤、卡在哪 |
| `shots_get` | `chapter`, `shot_ids?` | 采用版本里镜头的要点字段：编号、景别、画面、台词、时长；一次最多 20 个，不给 `shot_ids` 就取前 20 个 |
| `assets_find` | `query?`, `kind?` | 资产卡摘要：编号、类型、名字、别名、设定的前 200 字；最多 20 张 |
| `plot_get` | — | 主线剧情与各章梗概 |
| `film_status` | `chapter` | 各段状态、失败原因、已花与预估金额、合成状态 |
| `jobs_running` | — | 本小说在跑的任务、进度、最新一行日志 |
| `goto` | `chapter?`, `step` | 没有副作用；返回一个跳转目标，前端渲染为按钮 |

- 工具返回的文本最长 4000 字符，超出截断，并注明「还有 N 条未列出」。
- 返回里不含服务器路径、密钥、其他用户的任何信息。报错经过 `_hide_root`。
- `step` 取值与前端 `currentStep` 的六步一致。

## 5. 接口（子计划 1）

都依赖 `novel_user`（登录，且只能访问自己的小说；别人的返回 404）。

- `POST /novels/{nid}/assistant/messages`
  - 请求体：`{ text, lang, where: { chapter_id?, version_id?, step? } }`。
  - 返回 SSE（`text/event-stream`），事件：
    - `token` `{text}`：文字片段；
    - `tool_start` `{id, name, args}`：工具开始；
    - `tool_end` `{id, ok, summary}`：工具结束；
    - `goto` `{chapter_id?, step}`：跳转目标；
    - `done` `{}`：本轮结束；
    - `error` `{message}`：出错。
  - 实现：`agent.stream(..., stream_mode=["messages", "updates"])` 转成上面的事件。客户端断开时停止迭代，已生成的消息照常留在存档里。
- `GET /novels/{nid}/assistant`：返回历史，`{ messages: [{role, text, tools?, goto?}] }`，只给显示用的字段。
- `DELETE /novels/{nid}/assistant`：清空。没有存档也返回成功。

**限制**

- 每人每天的消息上限，环境变量 `STORYBOARD_ASSISTANT_DAILY`，默认 200。超过返回 429。按 UTC 日期计数，计数存在用量记录里。
- 同一部小说同时只跑一轮，进程内加锁；第二个请求返回 409。
- 用量：每轮结束（含中断、出错）按 `purpose="assistant"` 记一笔 `usage.record`，带 `novel_id`。管理后台的用量页照常可见。

## 6. 测试（子计划 1）

- **后端**（不调真实模型）：
  - 用 `GenericFakeChatModel`，或一个按脚本返回 `AIMessage(tool_calls=…)` 的假模型，驱动整轮对话。
  - 每个工具：返回字段、截断、章节解析与候选列表；对别人的小说拿不到数据。
  - SSE：事件顺序是 `tool_start` → `tool_end` → `token`… → `done`，`goto` 事件带对的目标。
  - 存档：两次请求之间历史接得上；`GET` 返回的历史正确；`DELETE` 之后为空，文件已删。
  - 历史裁剪：超过 20 条时发给模型的不超过 20 条，且不拆开工具调用与结果。
  - 限制：第 201 条返回 429；并发第二个请求返回 409。
  - 用量：一轮之后有一笔 `purpose="assistant"`。
  - 返回内容里没有服务器根路径。
- **前端**：
  - 发送、逐字显示、工具行的三种状态与展开；
  - 跳转按钮进对应章节和步骤；
  - 停止后标「已中断」；
  - 清空要确认；
  - 空对话示例问题；
  - 429 时禁用输入；
  - 输入法组字中 Enter 不发送。
- **冒烟**：`backend/assistant/smoke.py` 用真实模型对一部示例小说问一个问题，打印回答和用量。要花几分钱，由用户手动运行，开发与测试中不运行。

## 7. 子计划 2：发起操作（原则）

- **工具**：`generate_storyboard(chapter)`、`film_run(chapter, clip_ids?)`、`compose(chapter)`、`export_fcpxml(chapter)`。
  - 内部调用与接口相同的函数，因此鉴权、预估、花费上限、过期检查都相同。
  - 原先列的 `render_keyframes` 不做：服务端没有出图，关键帧是在别处出图后上传的（见 `useKeyframes.ts`）。
- **确认**：
  - 要花钱的工具先算预估（服务端），然后调用 `langgraph.types.interrupt({...})` 暂停。
  - SSE 发出 `confirm` 事件。
  - 前端在对话里渲染确认卡，上面有「确认」「取消」两个按钮。
  - 点按钮后调 `POST /novels/{nid}/assistant/resume`。服务端用 `Command(resume=…)` 接着跑，同样流式返回。
  - 恢复时按当前位置重算整张卡，章节、版本、要出的段、金额与要点有一样与卡上不一致就不执行，重新出卡（由助手再调一次工具出新卡，见 7.1）。
  - 不花钱的操作（例如导出）不出确认卡，直接执行。
- **进度**：执行后对话里出现一张任务卡，显示进度；完成后变成结果和跳转按钮。
- **未处理的确认卡**：存档里处在中断状态时，`GET` 返回这张待确认的卡。此时用户如果发新消息，先自动按「取消」处理这张卡。

### 7.1 四个操作（实施细节）

都作用于这一章的「采用版，没有就取最新可用版」（与只读工具同一个 `summary._pick_version`）。

| 工具 | 前提（不满足时工具报错，模型转述） | 预估 | 确认卡 | 执行 |
|---|---|---|---|---|
| `generate_storyboard(chapter?)` | 有原文；本章没有在跑的转换 | 无法预估模型费用：`amount=null`，卡上写「按模型用量计费」与原文字数 | 总要确认 | 与 `POST …/versions` 同一函数（含月度上限 429）；任务卡跟 `/jobs/{id}` |
| `film_run(chapter?, clip_ids?)` | 已有出片会话（用户在出片那一步选好了厂商与档位）；过验证门；不在合成中 | 与「出剩余各段 / 出这几段」同一套挑选与计价（`render_session.run_quote`），元 | 总要确认 | 与 `POST …/render/run` 同一函数，带卡上金额作确认金额；任务卡跟出片会话 |
| `compose(chapter?, draft=true)` | 过验证门；有 ffmpeg；说话人都有音色；非草稿时每段都有视频 | 未缓存配音字数 × 单价，元 | 金额大于 0 才确认；等于 0 直接执行 | 与 `POST …/render/compose` 同一函数；任务卡跟出片会话里的成片状态 |
| `export_fcpxml(chapter?)` | 成片已合成且没过期；有 ffmpeg | 不花钱 | 不出卡 | 只检查能否导出，对话里放「下载剪辑工程」按钮；点了由前端走现有下载接口 |

- **一次只发起一个操作**：模型绑定工具时关掉并行调用（`parallel_tool_calls=False`），每步最多一个操作，确认卡始终一张一张出、好推理，模型也不能在同一步里连发两个花钱的操作。
- **重新出卡**：恢复时工具从头重跑，按当前位置重算整张卡，与用户确认的那张卡（服务端从存档里取，不信前端）比较章节、版本、要出的段（出片卡顶层的 `clips`）、金额与要点（段数 / 字数）。有一样不一致就不执行，工具报「章节或版本变了，没有执行」或「预估变了（¥x → ¥y），没有执行」；确认后执行一律按卡上的章节、版本与段，出片只出卡上那几段，助手按提示词再调一次同一个工具，给用户出一张新卡。每次工具调用只中断一次：同一次调用里多次中断时，恢复会按顺序重放旧回答，而重放时的重算结果可能已经不同，用户最后的「取消」可能被前面的「确认」盖掉。
- **恢复的那次调用一律走确认**：合成金额为 0 本来不出卡；但恢复时如果配音刚好变成已缓存（金额变 0），工具重跑会跳过确认、无视用户的「取消」。所以恢复时服务端告诉工具「正在恢复哪一次调用」（`configurable.resume_tool_call`），这次调用不管金额多少都先取用户的回答。
- **确认金额照旧二次校验**：出片、合成执行时把卡上金额作为确认金额传进去，与界面上点按钮完全相同。

### 7.2 事件与接口

- **事件**（在第 5 节的基础上加两种）：
  - `confirm` `{id, tool_call_id, action, chapter_id, chapter, version_id, amount, currency, detail}`：出了一张待确认的卡。`id` 是 LangGraph 的中断编号。
  - `action` `{tool_call_id, action, outcome, card?, task?, error?}`：操作有了结果。`outcome` 取 `approved`（确认后已执行）/ `rejected`（取消）/ `done`（不需确认，已执行）/ `failed`（没做成，带 `error`）。`task` 为 `{kind: job|film|compose|export, chapter_id, version_id, job_id?}`。
  - 这四个操作工具不发 `tool_start` / `tool_end`，对话里不出现折叠的工具行，只出现卡片。
- `POST /novels/{nid}/assistant/resume`：请求体 `{id, decision: "approve"|"reject", lang, where}`。
  - 与发消息同样的鉴权、每日上限（算一轮、记一笔用量）、并发锁，同样返回 SSE。
  - `id` 不是当前待确认的卡：409「这张确认卡已经处理过」。
- `GET /novels/{nid}/assistant` 的每条助手消息多一个 `cards` 字段，形状与 `action` 事件相同；待确认的卡 `outcome="pending"`，`card` 里带 `id`。
- **发新消息时有待确认的卡**：服务端给这张卡补一条「已取消」的工具结果（不调模型），再开新的一轮；前端同时把本地的卡标成已取消。

### 7.3 前端

- **确认卡**：标题是操作名与章节。下面是金额（出片、合成写元；生成分镜写「按模型用量计费」）和要点（段数、配音字数、原文字数、「本章已有采用版，新版本只存档」）。待确认时有「确认」「取消」两个按钮，点了按钮在请求回来之前都禁用。
- **任务卡**（确认后或导出时出现在确认卡下方）：
  - 生成分镜：每 1.5 秒查任务，显示百分比；完成后给「去检查修改」，失败给原因；任务记录没了（服务重启）就说明一下。
  - 出片：每 5 秒查出片会话，显示「已出 n / 共 m 段，在跑 k 段」；没有在跑的段时结束，给「去出片」。
  - 合成：每 3 秒查出片会话里的成片状态；完成后给「去下载」，失败给原因。
  - 导出：一个「下载剪辑工程」按钮。
  - 卡片只在面板里显示时才查；关了面板就不查，再打开接着查。
- **页面联动**：操作开始后通知工作台：转换让任务巡检立刻刷新（动态里马上出现），出片和合成让正在看这一版的出片会话重读。
- 新文字进 `zh.ts` / `en.ts`。

### 7.4 测试

- **后端**（假模型、假出片与配音厂商；生成分镜把后台转换换成空函数，不调真实模型）：
  - 每个操作：出卡字段、确认后执行（出片真的排上队、合成真的开始）、取消不执行、金额变了不执行并报「预估变了」、确认后金额变回原值时用户的「取消」仍然有效、恢复时合成变成免费也照样尊重「取消」、合成金额为 0 不出卡、导出放下载按钮、前提不满足时报错。
  - 事件：`confirm` 之后流结束于 `done`；恢复后出 `action`；操作工具不发 `tool_start` / `tool_end`。
  - 历史：待确认的卡 `pending` 带 `id`；处理过的卡带结果。
  - 接口：恢复的鉴权、409（卡已处理）、422（decision 非法）、429、用量一笔；有待确认的卡时发新消息，卡变「已取消」，模型看到取消结果与新问题。
- **前端**：确认卡的几种状态与按钮；点确认发恢复请求并禁用按钮；任务卡的进度文字与完成后的跳转；发新消息时待确认的卡标成已取消；`action` 事件通知工作台。

## 8. 子计划 3：改内容（原则）

- **工具**：`shots_edit(chapter, edits)`、`asset_edit(card_id, fields)`、`plot_edit(...)`。
  - 模型给出要改成什么，服务端算出改动对比，然后 `interrupt` 暂停。
- **对比卡**：前端按字段逐条显示「原 → 新」，带「应用」「放弃」两个按钮。之后同样走 `resume`。
- **应用**：
  - 改镜头：与界面上「保存修改」相同，在这一版上直接保存并整份复验。原写的「生成新版本」与界面行为不符，而且新版本没有这一版已出的片段和关键帧，所以不做。
  - 改资产卡和主线剧情：直接写入。
  - 撤销要用的「改之前的值」只记改动的那几处，存在这次工具结果里（服务端存档）。
- **撤销**：对比卡在应用后变成「已应用 · 撤销」。点撤销把那几处写回改之前的值。要求那几处在这之后没被别处再改过，否则提示无法撤销。

### 8.1 三个工具（实施细节）

| 工具 | 能改的 | 不能改（工具直接拒绝） | 应用 |
|---|---|---|---|
| `shots_edit(chapter?, edits[])` | 每处 `{shot_id, field, value}`：`action` 画面、`atmosphere` 氛围、`shot_size` 景别、`duration_sec` 时长（0.5–15 秒）、`camera.movement` 运镜、`camera.angle` 机位、`transition_out` 转场、`sfx` 音效（列表）；枚举值与 schema 一致；一次最多 20 处 | 旁白与台词（原文逐字）、溯源、别的字段 | 与 `PUT …/versions/{vid}` 同一函数：整份复验后保存；复验不过照样保存，版本标成草稿（与界面相同）。对比卡上预先写出复验不过的原因 |
| `asset_edit(card_id, fields)` | 卡上已有的文字字段（字符串，或字符串列表如别名）；嵌套字段用点号，如 `appearance.face` | 编号、服装、状态、角度、参考图；卡上没有的字段；名称不能为空 | 与资产卡接口同一函数（`novels.upsert_asset`） |
| `plot_edit(outline?, chapter?, synopsis?)` | 全书梗概；某一章的梗概 | — | `novels.set_outline` / `set_synopsis` |

- 镜头编号接受完整编号（`E01-SH003`）或唯一的后半段（`SH003`）。
- 改成与原来相同的地方不列进对比；一处都没变就报错，不出卡。
- 都作用于「采用版，没有就取最新可用版」（与只读工具相同）。
- **恢复时核对**：与 7.1 相同，工具从头重跑，按当前位置重新算一遍对比。章节、版本或任何一处的「原 / 新」与用户看到的卡不一样，就不应用，报「要改的内容或位置在这之后变了」。

### 8.2 卡片、事件与接口

- 沿用 `confirm` / `action` 事件（不另设 `diff` 事件）。卡片多两个字段：
  - `diff`：`[{target, field, before, after}]`，值都转成显示用的文字；
  - `warnings`：复验不过的原因，最多 5 条。
- 应用后 `action` 的 `outcome="approved"`，`task={kind:"edit", chapter_id, version_id}`。撤销用的数据只留在存档里，不发给前端。
- `POST /novels/{nid}/assistant/undo`，请求体 `{tool_call_id}`：
  - 不调模型、不记用量，要拿到并发锁（正在回答时 409）。
  - 已经撤销过的 409；找不到这次修改 404；那几处之后被改过 409（附原因）。
  - 成功返回 `{ok, message, task}`。
- 撤销过的记在 `<小说目录>/assistant.sqlite.undone.json`，清空对话时一起删。`GET` 历史里这些卡 `outcome="undone"`。
- **页面联动**：应用或撤销后通知工作台。
  - 改镜头：正在看的这一版没有未保存的修改，就重读；有未保存的修改，就提示「助手改了这一版，你保存时会覆盖它的修改」，不重读。
  - 改资产卡、主线剧情：重读小说。

### 8.3 测试

- **后端**：
  - 每个工具：对比字段、不能改的被拒、没变化报错、应用后的数据、取消不改、恢复时内容变了不应用。
  - 改镜头复验不过：卡上有原因，应用后版本是草稿。
  - 撤销：写回、之后被改过拒绝、撤销两次 409、正在回答时 409、历史里显示已撤销、清空对话删掉记录。
- **前端**：
  - 对比卡显示「原 → 新」、复验警告与「应用」「放弃」；
  - 应用后有「撤销」，点了变「已撤销」，失败给提示；
  - 撤销与应用都通知工作台。

## 9. 不做

- 一部小说多串对话、对话搜索、导出对话。
- 书架页的跨小说助手。
- 语音输入、上传图片给助手。
- 让模型自己决定花钱、跳过确认。
- 助手修改小说参数、删除章节或版本、删除小说。
- 后端报错文字英文化（另一件事）。
