# 风格参考图设计

日期：2026-11-01。

背景：工作台改版规格（`docs/specs/2026-11-01-workspace-redesign-design.md`）第 11 节第 4 条列了三项后续，用户定了先做风格参考图。

## 0. 目标

- 用户可以给一部小说上传一张风格参考图，存在服务端。
- 出片时，每段在参考位上带上这张图，让画风、色调、光线跨段保持一致。
- 关键帧提示词旁边可以下载这张图，方便拿去外部工具出图时一起用。
- 换图不让已出好的片段过期，不会意外花钱。

## 1. 现状

- **出片时的参考图**：
  - 来源是资产卡的 `reference_images[].uri`，以及场景卡的 `angles[].uri`（`render/compose.py` 的 `image_for`）。
  - 只认 `http(s)` 地址或 `data:image` 开头的值。
  - 每段按优先级保留，最多保留 `caps.max_refs` 张（方舟 Seedance 是 9 张）。优先级是：本段主要角色 > 场景 > 次要角色与生物 > 道具（`pick_refs`）。
- **首帧与参考图互斥**：方舟的 `frame_with_refs=False`，首帧和参考图不能同用。
  - 段首镜头有关键帧时，关键帧占第一个参考位（`frame_mode="ref"`）。
  - 本段没有参考图时，用同一集上一段的尾帧接力（`frame_mode="frame"`）。
- **能上传的图只有关键帧**：每版本每镜一张，PNG / JPEG / WebP，不超过 8MB（`server/novels.py` 的 `save_keyframe`）。发给厂商时转成 base64 的 `data:image` 值。
- **风格目前只是文字**：小说参数里的 `style_prefix`、`art_style` 写进提示词。子计划 1 里，风格卡片可以换成本机图片，但那只用来显示（存在浏览器里）。
- **片段指纹**（`compose.fingerprint`）：由镜头内容、提示词、参考图哈希、首帧、厂商、档位、分辨率、声音模式算出。尝试的指纹和片段指纹不一致时，片段状态是 `stale`（已过期）。

## 2. 用户能看到的

### 2.1 设置页：上传

- 小说设置页的「风格」区加一个「风格参考图」框：
  - 空着时是虚线框，写「拖入或选择一张图（PNG / JPEG / WebP，≤ 8MB）」。
  - 有图时显示缩略图，旁边是「替换」「删除」两个按钮。删除走 `useConfirm`。
  - 一行说明：「出片时每段会带上这张图来统一画风；换图不会让已出的片段过期。」
- 上传、删除成功都弹 `notice`。失败时显示后端的报错文字。
- 每部小说**只有 1 张**。多张会多占参考位，把角色参考图挤掉，所以不做。

### 2.2 概览页

- 故事梗概卡片的右上角显示风格图的小缩略图（48px 圆角）。点一下进设置页。
- 没有风格图时不显示。

### 2.3 画布：出片页

- 每段的详情里加一行「风格图」，取值有四种：
  - **已带上**：「风格图 ✓」。
  - **没带上，因为参考位满了**：「未带上：参考位已满」。
  - **没带上，因为用了首帧**：「未带上：本段用首帧（关键帧或上一段尾帧）」。
  - **没有风格图**：这一行不显示。
- 某段采用的那次尝试用的是旧风格图（或当时没有风格图），而现在有新图时，显示提示「风格图已换，可重出这一段」，配语义色 `warn` 的 `StatusPill`。
  - 这一段的状态仍是 `done`，不算过期。
  - 批量「出剩余各段」不包括它。
  - 用户手动点这一段的「重出」时，照常走预估和确认。
- 出片页顶部的汇总里加一个计数：「N 段可按新风格图重出」，为 0 时不显示。

### 2.4 画布：关键帧页

- 关键帧提示词列表的顶部，有风格图时显示缩略图和「下载风格图」按钮，方便和提示词一起拿去外部工具出图。
- 复制、下载提示词的内容不变。

## 3. 出片时怎么带上

### 3.1 参考位

- 风格图在参考位里的角色是新的 `style`。`asset_id` 固定为 `"__style__"`，不会和资产卡 ID 冲突：资产卡 ID 是 C/S/P/A 开头加数字。
- **优先级**：本段主要角色 > **风格图** > 场景 > 次要角色与生物 > 道具。
- **首帧优先**：本段用了首帧时，风格图不能破坏首帧：
  - 厂商不能首帧与参考图同用（`frame_with_refs=False`）且本段 `frame_mode="frame"`（首帧单用）时，不带风格图。厂商能同用时照常带。
  - 尾帧接力原本要求本段没有参考图。风格图不算进这个判断，所以带不带风格图都不影响接力。
  - `frame_mode="ref"`（关键帧占第一个参考位）时，风格图照常参与排序，占剩下的参考位。
- 参考位不够时按优先级裁掉，风格图被裁掉就记「参考位已满」。

### 3.2 提示词

- 带上风格图时，在提示词的参考图说明后面加一句：「参考图 N 是画风参考：沿用它的色调、线条与光影，不要照搬其中的人物或场景内容。」N 是风格图在请求里的序号。
- 改写成厂商语法时（`rewrite_refs`），这一句和其他参考图占位符一样处理。

### 3.3 图片的传法

- 和关键帧一样，读文件转成 `data:<mime>;base64,…` 放进 `RefImage.source`，`role="style"`。
- `providers/base.py` 的 `REF_ROLES` 加上 `style`。
- 方舟的请求里，风格图和其他参考图一样作为参考图传；`fake` 厂商照收。

## 4. 指纹与「可重出」提示

- **片段指纹不含风格图**：
  - `build_clips` 先按现在的逻辑选参考位、拼提示词、算指纹，这一步完全不知道风格图。
  - 然后再插入风格图参考位，补上提示词里那一句。
  - 所以有没有风格图、换没换图，片段指纹都不变，已出的片段不会变成 `stale`。
- **发给厂商的是带风格图的版本**：片段上新增：
  - `style`：`"used" | "full" | "first_frame" | null`。`null` 表示没有风格图。
  - `style_hash`：这次要用的风格图哈希，没用就是 `null`。
  - 落盘的 `prompt` 是带风格句的那一版。界面上看到的就是实际发出的内容。
- **每次尝试记下当时用的风格图**：`attempts[].style_ref`，取发起尝试时片段的 `style_hash`。
- **「可重出」的判定**：同时满足下面三条时，在读出片会话的接口里给这一段加 `style_outdated: true`：
  - 片段状态是 `done`；
  - 现在有风格图，且本段 `style == "used"`；
  - 采用那次尝试的 `style_ref` 不等于当前风格图哈希。
  
  会话汇总加 `style_outdated_count`。
- **为什么不把风格句算进指纹**：风格句一加，提示词就变了；如果提示词进指纹，有没有风格图就会改变指纹，这与第 0 节「换图不过期」矛盾。代价是：同一段的两次尝试可能用了不同的风格图，而指纹相同。这正是「可重出」提示要告诉用户的事。

## 5. 后端

- **存储**：
  - 小说目录下放 `style/style.<ext>`，一部小说只有一个文件，替换时先删旧的。
  - 小说记录加 `style_image: { hash, mime, bytes, updated_at } | null`。哈希是文件内容的 sha256。
- **接口**（都要登录，只能操作自己的小说，写法照搬关键帧那组）：
  - `GET /novels/{nid}/style-image`：取图（原始图片体）。没有返回 404。
  - `PUT /novels/{nid}/style-image`：上传，请求体是原始图片，`Content-Type` 为 PNG / JPEG / WebP，不超过 8MB，与关键帧同一个上限常量。返回 `style_image` 元数据。
  - `DELETE /novels/{nid}/style-image`：删除。没有也返回成功。
  - 小说详情接口返回的 novel 里带上 `style_image` 元数据，前端靠它判断有没有图、拿缩略图。
- **出片会话**：建会话、刷新片段时（`session.py` 调 `compose.build_clips` 的地方），读取这部小说的风格图，作为新参数 `style={"source": data_uri, "hash": …} | None` 传入。读不到文件时当作没有风格图，不报错。
- **不改**：转换（分镜生成）流程不用风格图；`style_prefix` 照旧。

## 6. 前端

- `api.ts`：新增 `getStyleImageUrl(nid)`、`uploadStyleImage(nid, file)`、`deleteStyleImage(nid)`。
  - `getStyleImageUrl` 带 token 取回 blob，转成 blob URL，与 `keyframeUrl` 一样，用完要 revoke。
- `types.ts`：
  - `Novel.style_image`。
  - `FilmClip.style`、`style_hash`、`style_outdated`。
  - `FilmAttempt.style_ref`。
  - `FilmSession.style_outdated_count`。
- 新钩子 `useStyleImage(novel)`：按 `novel.style_image?.hash` 取 blob URL，哈希变了重取，卸载时回收。设置页、概览页、关键帧页共用。
- 设置页的上传框是新组件 `StyleImageField`，放在 `src/components/params/` 下，与子计划 1 的参数组件放在一起。
- 所有新文字进 `zh.ts` / `en.ts`。
- 后端的报错文字仍是中文，与现有接口一致。英文化后端报错是另一件事。

## 7. 测试

- **后端**：
  - 上传、读取、删除；格式不对、超过 8MB、空文件都报错；别人的小说返回 404；替换时旧文件被删掉。
  - `build_clips` 带风格图时：
    - 有空位，`style == "used"`，参考位顺序是主要角色在风格图前、风格图在场景前。
    - 参考位满了，`style == "full"`。
    - `frame_with_refs=False` 且 `frame_mode="frame"` 时 `style == "first_frame"`；`frame_with_refs=True` 时照常带上。
    - 尾帧接力不因为有风格图而失效。
  - **同一份分镜，没有风格图、有风格图 A、有风格图 B 三种情况下，各段指纹完全一样。**
  - 提示词里带上了风格句，序号与参考图顺序一致。
  - `style_ref` 在发起尝试时写入。
  - 换图后，采用尝试用的是旧图的 `done` 段，会出现 `style_outdated`，并计入 `style_outdated_count`；这一段仍是 `done`，批量「出剩余各段」的预估和执行都不包括它。
- **前端**：
  - `StyleImageField`：空态、上传后显示缩略图、删除需要确认。
  - 画布出片页：四种「风格图」行文案，以及「可重出」提示和计数。
  - 概览页：有图时显示缩略图，点了进设置页。
- **冒烟**：真实方舟带参考图出片要花钱，交给用户手动跑。现有 `render/smoke.py` 加一个可选参数 `--style <图片路径>`。

## 8. 不做

- 一部小说多张风格图。
- 把风格图交给大模型，改写 `style_prefix`。
- 资产卡直接上传参考图（另议）。
- 子计划 1 风格卡片的本机换图（只用于显示），保持原样，和这张风格图无关。
- 按章节设不同的风格图。
